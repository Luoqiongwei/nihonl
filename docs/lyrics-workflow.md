# 歌单筛选与歌词查证工作流

本流程面向从 Bilibili 视频标题直接导出的歌单。标题只作为检索线索，不能单独作为歌名、歌手或演唱语言的证据。

## 1. 输入清洗

1. 保留原始标题与原始序号，统一 Unicode（NFKC），清理搬运、字幕、画质、投稿类型等包装标签。
2. 分离候选歌名、歌手/声库、企划、版本信息；中文译名与日文原名都保留为检索别名。
3. 对相同标准化歌名及同一来源 URL 去重。翻唱与原唱在学习内容相同且歌词一致时只保留一个主条目，并在歌手字段注明版本。

## 2. 演唱语言判定

按证据强度依次判断：

1. 官方投稿说明、官方歌词页或发行页明确标注的歌词语言；
2. 可核对的歌词正文：日文假名/日语语法占主要篇幅则记为日语；
3. 声库与歌手只作为候选信号，不能单独定案；中文声库可能唱日语，日语声库也可能唱中文或英文；
4. 中日混唱且包含可独立学习的日语段落可以收录，并明确标记混合语言；纯中文、纯英文、纯音乐、专辑/XFD/活动视频排除；
5. 无法确认时保持 `unresolved`，不靠标题字符猜测入库。

## 3. 歌词来源优先级

逐级查找，命中后仍要核对歌名、歌手/声库和至多三句正文样本：

1. 作者或版权方官方投稿、官方网站、PIAPRO、官方发行页；
2. Vocaloid Lyrics Wiki / 初音ミク Wiki（适合 VOCALOID、UTAU、CeVIO）；
3. 歌ネット、UtaTen、J-Lyric、JOYSOUND、TuneCore/PetitLyrics 等正规歌词或发行平台；
4. 网易云等带原文与翻译的音乐平台；
5. 可追溯到原作者的翻译页或社区资料，仅作交叉核对，不作为唯一作品身份来源。

现有自动化顺序是：

```text
analyze_songlist.mjs
  → lookup_lyrics.ps1（Vocaloid Lyrics Wiki）
  → lookup_utaten.ps1（UtaTen）
  → lookup_netease.ps1（网易云）
  → 人工兜底（官方投稿 / 初音ミク Wiki / 歌ネット / J-Lyric / JOYSOUND 等）
```

## 4. 入库规则

每首歌至少包含：

- 稳定且唯一的 `id`；
- 标准歌名、歌手、企划，以及已知时的作词/作曲与年份；
- `lyricsStatus`；
- 至少两个短日文学习节选及中文释义；
- 至少两个词汇或语法学习点；
- 至少一个可复核来源 URL；
- 原歌单序号 `sourceNo`，便于回溯标题解析问题。

未经明确授权的完整第三方歌词不得写入仓库、生产数据库、构建产物或备份。自动查证文件只允许短期保留来源元数据和最多三行语言核验样本，人工确认并录入 `excerpt` 后立即删除。

若将来取得书面授权，可在与生产网站隔离的受限存储中使用以下归档结构，前台仍只读取 `excerpt`：

```js
{
  fullLyrics: {
    text: '...',
    language: 'ja',
    license: '授权名称或协议',
    rightsHolder: '权利人',
    sourceUrl: 'https://...',
    retrievedAt: 'YYYY-MM-DD',
    display: false
  }
}
```

没有明确授权信息时，只保存来源链接与 2–3 句短学习节选。网页源码、静态 JSON、API、日志和备份均不得出现完整歌词。

## 5. 质量检查

1. 检查歌曲、词汇、语法 ID 唯一且引用存在；
2. 对标题相近条目人工检查是否重复；
3. 运行 `node scripts/convert_data.mjs` 生成 `src/data/`；
4. 运行 `pnpm test` 与 `pnpm build`；
5. 抽查音乐列表、详情页、来源链接和移动端布局。
6. 删除 `data/*.html`、`data/lyrics-*.json`、LRC、TTML、响应转储以及其他抓取缓存。
